# Taste
- Prefers extraction/processing results persisted to disk rather than only returned in memory or printed to the console, each result type written to its own format-appropriate file (e.g. `.md`/`.txt`/`.json` for document output, `.csv` per table, `.png` per image). Confidence: 0.55
- Reports problems by pasting raw IDE context + the full stack trace with little to no surrounding explanation, expecting the agent to diagnose the root cause and apply the fix directly rather than asking them to describe the issue. Confidence: 0.6
- Keeps frontend and backend as separate projects — wants the React frontend in its own folder outside the backend repo rather than a single combined workspace. Confidence: 0.55
- Prefers exposing the processing pipeline through a thin HTTP API layer rather than importing pipeline code directly into the UI. Confidence: 0.5
- Prefers ReactJS (Vite) for frontend apps. Confidence: 0.55
- Prefers FastAPI (with uvicorn) over Flask for Python web APIs. Confidence: 0.6
- Wants asynchronous operations surfaced in the UI with a loading indicator followed by explicit success/failure states. Confidence: 0.5
- Concerned about intermediate artifacts accumulating on disk; prefers temporary inputs/outputs be cleaned up once their content has been persisted downstream (e.g. delete the uploaded PDF and parsed output after chunks are in the vector store) rather than leaving folders to grow unbounded. Confidence: 0.5
- Prefers downstream modules (e.g. retrieval) import and reuse the shared configuration/objects and accessor functions defined by the ingest module — the index accessor, embedding model, vector DB client — rather than declaring their own or re-deriving the index locally (e.g. prefer importing `create_or_return_index` over importing the raw `pinecone` client and calling `pinecone.index(...)`), so read and write paths stay on the same index and vector space. Confidence: 0.65
- Gives terse, loosely spelled instructions with the target file supplied via IDE context, expecting the agent to infer intent, inspect the file, and implement it without back-and-forth. Confidence: 0.55
- When asking a feasibility question (e.g. "can we use X for Y?"), wants an assessment/answer first and to settle approach and tradeoffs before any code is written — prefers the agent not to jump straight into implementation for exploratory questions. Confidence: 0.55
- Interested in hybrid retrieval — combining lexical BM25 search with dense vector search over the same corpus. Confidence: 0.55
- Prefers the agent to leave explicit `TODO:`-style inline comments marking exactly where future/planned functionality (e.g. reranking) should be plugged in, rather than implementing it or silently omitting it — so the extension point is obvious in the code. Confidence: 0.6
- Prefers incremental delivery: have the agent implement one usable piece now ("for now add bm25") and defer the advanced follow-up work (e.g. reranking) to be done later, rather than building the whole feature in one pass. Confidence: 0.55
- Sometimes writes/edits a feature himself and then asks the agent to verify it (e.g. a terse "now included bm25 check once"), expecting a focused review that hunts for integration/logic bugs and dead code rather than a from-scratch re-implementation. Confidence: 0.5
- Frequently asks the agent to explain specific code snippets/constructs (e.g. a dict comprehension + `dict.update` collision semantics, or whether a function loads-and-rebuilds an index) to understand how the existing code behaves, rather than requesting a change — expects a line-by-line walkthrough of the mechanics plus edge cases/precedence. Confidence: 0.55
- Organizes the RAG pipeline into separate folders/modules per stage (e.g. `ingestion/`, `rtrival/`, `aug/`), preferring each stage live in its own file that imports the previous stage's output rather than one monolithic module. Confidence: 0.5
- Wants the generation step decoupled from retrieval: a function that takes the already-computed search results plus the question (e.g. `answer(question, results)`) rather than only a single entrypoint that runs retrieval internally. Confidence: 0.5
- For multimodal content (images/figures), prefers the derived text (e.g. a vision-model caption) be embedded with the *same* embedding model into the *same* index/vector space as regular text chunks, so one existing search path serves both — rather than a separate per-modality index with its own query path. Confidence: 0.5
- Distinguishes "the code exists / compiles / smoke-tested" from "the data path actually ran": when he asks whether a feature is working (e.g. "how can we check whether the embedding is working for images", or a terse "check now what it gives response" for a real question), expects verification by actually running it — querying the vector store's stats/metadata for the expected records, or running the full retrieval+generation pipeline end-to-end on a real sample question and reporting the concrete generated answer/sources — and explicitly reporting `0`/empty when nothing has been written, rather than a claim based on a successful call. Confidence: 0.55
- Expects a script's standalone entrypoint (e.g. `main()` in `indx.py`) to run the *complete* pipeline for every stage, not just the piece the agent most recently wired into the API route — new steps should be added to the directly-runnable entry point too, so "just run the script" and the HTTP path stay at parity instead of one silently covering only part of the work. Confidence: 0.55
- Runs pipeline/ingest scripts himself (rather than always asking the agent to), so expects the agent to accept that the step has already been executed and reason about what that run actually covered instead of proposing to run it again. Confidence: 0.5
- Runs the services himself and repeatedly asks for the exact start command (e.g. a terse "command to run backend?"), expecting a copy-pasteable command with the working directory, venv/`python -m` form, port, and the companion process (frontend dev server + URL) spelled out rather than just a pointer to docs. Confidence: 0.45
- Prefers new user-facing capabilities delivered end-to-end: a backend HTTP endpoint *and* the matching frontend UI control (button/form + success/error feedback), rather than a backend-only change — e.g. asking for a "reset" as "one api and frontend functionality" to clear indexed data so a user can upload a new PDF. Confidence: 0.5
- Works in the same files concurrently with the agent — his editor saves over the agent's edits (e.g. dangling partial lines like `bm_res = ` appearing mid-run), so the agent should re-read the current file state before editing and be ready to reconcile/reload rather than assuming its buffer matches disk. Confidence: 0.5
